# 🌒 LOST EDEN · Discord Bot

> **We don't return. We rebuild.**

Discord-бот для сервера **LOST EDEN · RIMAY**, написанный на Python с использованием `discord.py`.

Проект развивается как собственная система сервера: профиль участника, прогресс, экономика, достижения, ритуалы, коллекционные награды, EVENT / DUEL / CLOSE, верификация и административные инструменты связаны между собой и оформлены в едином стиле LOST EDEN.

---

## About

**LOST EDEN Bot** создаётся специально для Discord-сервера **LOST EDEN · RIMAY**. Это не универсальный бот-комбайн. Его задача — быть частью самого сервера: встречать новых участников, хранить их прогресс, открывать путь внутрь Сада, поддерживать игровые активности и связывать уровни, роли, награды и экономику.

Основные принципы проекта:

- slash-команды на русском языке;
- интерактивные интерфейсы через `discord.ui`;
- единый визуальный стиль embed-сообщений;
- графические карточки через Pillow;
- постоянное хранение статистики в SQLite;
- разделение Discord-интерфейса, бизнес-логики и базы данных;
- восстановление persistent-интерфейсов после перезапуска;
- минимум лишнего функционала;
- механики, поддерживающие атмосферу **Lost Eden / Paradise**.

# Реализованные системы

## Профиль участника

Команда `/профиль` формирует графическую карточку участника на основе `assets/profile_template_v2.png`.

Карточка показывает реальные данные:

- аватар и имя;
- Discord username;
- уровень;
- место в рейтинге;
- общий XP;
- XP до следующего уровня;
- баланс;
- EDEN CASES;
- статус верификации;
- текущую юбилейную роль;
- сообщения;
- время в голосовых каналах;
- достижения;
- количество DUEL;
- количество CLOSE.

Под карточкой дополнительно выводятся участия в EVENT, победы и winrate в DUEL / CLOSE. Подробная сводка доступна через `/прогресс`.

Старая дублирующая реализация `/профиль` удалена. В проекте используется единая актуальная команда.

---

## Прогресс и уровни

Бот автоматически собирает активность участников и переводит её в общую систему прогресса.

Учитываются сообщения, голосовое время, XP, уровень, рейтинг, EVENT, подтверждённые DUEL и CLOSE, достижения и ежедневный ритуал.

За повышение уровня выдаётся **1 EDEN CASE за каждый полученный уровень**, в том числе если участник перескочил сразу через несколько уровней.

Основные команды:

```text
/прогресс
/рейтинг
```

---

## Юбилейные роли

Milestone-роли уже настроены в `config/roles.py`:

```text
5   → Росток
10  → Укоренившийся
20  → Под ветвями
35  → Голос Сада
50  → Возрождённый Эдем
```

Участник хранит только самую высокую доступную юбилейную роль. Названия Discord-ролей должны точно совпадать с конфигурацией, а роль бота должна находиться выше них.

Для ручной синхронизации предусмотрены `/роль-уровня` и `/обновить-роль-уровня`.

---

## EDEN CASES

`/кейсы` открывает личное хранилище EDEN CASES.

Кейсы выдаются за уровни, могут выступать наградами достижений, ритуалов и EVENT, а также покупаются в магазине. Открытие происходит через интерактивную кнопку.

Помимо обычных наград, в EDEN CASES встроен редкий шанс получить коллекционный **Bloom**.

---

## Экономика

Внутренняя валюта называется **Средства** и обозначается `🍎`.

Экономика используется в:

- наградах за активности;
- достижениях;
- ритуале;
- EDEN CASES;
- магазине;
- казино;
- административных начислениях и списаниях.

Баланс меняется через отдельный слой экономики. Покупки и награды не работают напрямую с таблицей профиля.

### Магазин

Добавлены команды:

```text
/магазин
/купить-кейс
```

Сейчас стабильный товар магазина — EDEN CASE. Это создаёт постоянный расход Средств и помогает удерживать баланс экономики. Стоимость и лимиты покупки хранятся в `config/economy.py`.

---

## Blooms

**Blooms** — редкие коллекционные находки LOST EDEN, а не вторая обычная валюта.

В базовом каталоге есть:

```text
Ash Bloom    · Rare
Moon Bloom   · Epic
Crown Bloom  · Legendary
```

Команда:

```text
/цветы
```

показывает коллекцию участника, найденные виды и их количество.

Blooms сохраняются в SQLite и могут выпадать из EDEN CASES. Для специальных событий администратор может использовать:

```text
/выдать-цветок
```

---

## Достижения

`/достижения` показывает условия, текущий прогресс и награду каждого достижения.

Достижения могут учитывать сообщения, voice time, активности, матчи, победы и winrate. Поддерживаются награды Средствами и EDEN CASES.

---

## Ежедневный ритуал

`/ритуал` доступен раз в 24 часа. Ритуал выдаёт награду и сохраняет время следующего использования. Его состояние также отображается в `/прогресс`.

# EVENT / DUEL / CLOSE

Проект использует общий фундамент активностей с отдельной логикой для каждого режима.

## EVENT

Управляющий сервером может создать EVENT, задать описание, лимит участников и награды. Участники записываются через кнопки.

```text
/создать-ивент
/запустить-ивент
/завершить-ивент
/отменить-ивент
/награда-ивента
/ивенты
```

После завершения поддерживаются автоматические награды и защита от повторного начисления.

## DUEL

DUEL — персональный матч двух участников.

```text
/дуэль
/результат-дуэли
/отменить-дуэль
/дуэли
```

Один участник предлагает результат, второй подтверждает его. Только подтверждённый результат попадает в статистику. Открытые DUEL и ожидающие подтверждения состояния восстанавливаются после перезапуска бота.

## CLOSE

Поддерживаются:

```text
2×2
3×3
4×4
5×5
```

Команды формируются случайно либо через капитанов. При капитанском режиме капитаны и первый пик выбираются случайно, затем выбор идёт по очереди.

```text
/создать-клоз
/запустить-клоз
/выбрать-игрока
/результат-клоза
/подтвердить-клоз
/отменить-клоз
/клозы
```

Результат должен быть подтверждён представителем проигравшей команды. Участники получают XP за участие, победители получают дополнительный бонус. Для наград действует дневной лимит.

# Верификация

Верификация использует одну Discord-роль. Её ID задаётся через:

```env
VERIFIED_ROLE_ID=123456789012345678
```

Discord-роль является источником истины.

Администратор один раз публикует панель:

```text
/панель-верификации
```

Участник нажимает **«Пройти верификацию»**, после чего получает роль. View постоянная и продолжает работать после перезапуска бота.

Ручное управление:

```text
/верифицировать
/снять-верификацию
```

Роль бота должна находиться выше роли `Верифицирован`, а у бота должно быть право `Управлять ролями`.

Рекомендуемая схема Discord:

```text
Администратор
LOST EDEN BOT
Модератор
Верифицирован
Юбилейные роли
Обычные роли
@everyone
```

Для входной категории `@everyone` получает просмотр, а `Верифицирован` может быть скрыт. Для основных категорий схема обратная: `@everyone` не видит каналы, `Верифицирован` получает доступ.

# Администрирование

## Журнал действий

Административные slash-команды автоматически фиксируются в SQLite. Журнал хранит исполнителя, действие, параметры и время.

Просмотр:

```text
/аудит
```

В журнал попадают, среди прочего, операции верификации, экономика, milestone-роли, выдача Blooms и управление EVENT / DUEL / CLOSE.

## Диагностика

Команда:

```text
/проверка-системы
```

проверяет:

- доступность SQLite;
- наличие шаблона профиля;
- необходимые права бота;
- `VERIFIED_ROLE_ID`;
- существование роли верификации;
- положение роли бота в иерархии;
- наличие всех юбилейных ролей и возможность ими управлять.

Перед запуском сервера рекомендуется добиться состояния `SYSTEM CHECK · READY`.

# Настройка

## 1. Клонирование

```bash
git clone https://github.com/smalltalk-eater/dark-dis-bot.git
cd dark-dis-bot
git switch smalltalk
```

## 2. Virtual environment

Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 3. `.env`

Создай `.env` на основе `.env_example`:

```env
DIS_TOKEN=YOUR_DIS_TOKEN
GUILD_ID=YOUR_GUILD_ID
WELCOME_CHANNEL_ID=YOUR_WELCOME_CHANNEL_ID
VERIFIED_ROLE_ID=YOUR_VERIFIED_ROLE_ID
```

Не добавляй настоящий `.env` в Git.

## 4. Запуск

```bash
python bot.py
```

После старта бот инициализирует БД, загружает расширения и синхронизирует slash-команды для заданного `GUILD_ID`.

# Docker и 24/7-развёртывание

В репозитории готовы `Dockerfile` и `docker-compose.yml`.

Запуск:

```bash
docker compose up -d --build
```

Контейнер настроен с `restart: unless-stopped`, а каталоги `data` и `backups` монтируются наружу, чтобы база и резервные копии не исчезали при пересоздании контейнера.

Проверка логов:

```bash
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

Конкретный VPS / хостинг выбирается отдельно. Docker-конфигурация уже позволяет перенести проект на обычный Linux-сервер без изменения архитектуры бота.

---

# Резервные копии SQLite

Для безопасного копирования `data/eden.db` есть:

```text
scripts/backup_db.py
```

Запуск:

```bash
python scripts/backup_db.py
```

По умолчанию сохраняются последние 14 копий в `backups/`.

Можно изменить количество:

```bash
python scripts/backup_db.py --keep 30
```

Копирование выполняется через SQLite Backup API, поэтому безопаснее обычного копирования файла работающей базы.

На production-сервере этот скрипт рекомендуется запускать по расписанию cron или средствами хостинга.
